# Evaluation method

`anomaly-detection-eval` replays synthetic series through the same model and pipeline code
that the sidecar runs, and scores the outcome on events, not on single samples.

## Data

Generated by `anomaly_detection.harness.synth`, reproducible from a seed.

| signal | shape |
|---|---|
| `request_rate` | base 120, daily harmonics (peak 15:00), weekend factor 0.65, +1 percent per week, 6 percent autocorrelated noise |
| `output_tokens` | base 280, +-5 percent daily, 3 percent noise |
| `throughput` | base 12000, +-2 percent daily, 1.5 percent noise, a 30 percent dip for two samples once an hour (checkpointing, normal) |
| `step_time` | derived: 96000 / throughput, plus 1 percent noise |

0.2 percent of samples are missing. Missing samples are skipped, never zero-filled.

Each case is 14 days of normal training data followed by an evaluation period (7 days for the
scenarios, 14 days for normal-only series). The models see the whole stream online, the way the
sidecar sees backfill and live data; only alerts in the evaluation period count.

## Scenarios

One anomaly of 60 to 240 minutes per scenario case, at a random time at least 12 hours into
the evaluation period. Even variants drop instantly, odd variants ramp over 5 minutes.

| scenario | signal, direction | injection |
|---|---|---|
| `request_drop` | `request_rate`, below | half of the variants fall to 0-5 percent of normal, half to 10-50 percent |
| `token_length_drop` | `output_tokens`, below | mean length becomes 1 to 3 tokens |
| `throughput_drop` | `throughput`, below | throughput falls to 45-55 percent |
| `step_time_rise` | `step_time`, above | the step time that follows from the same throughput drop |

Normal-only series use direction `both`, the worst case for false alarms, and are the source of
the false alarm rate per series per day.

## Alerts and metrics

- The alert rule is `score >= 0.5` for 3 consecutive samples (like `for: 3m` at a 60 second step).
  The alert fires at the third sample.
- Runs of high scores separated by at most 10 samples are one alert.
- A true event is detected when an alert fires from the event start until 5 samples after its end.
  Detection delay is the time from event start to that alert.
- Any alert that matches no event is a false alarm.
- Precision is matched alerts over all alerts, recall is detected events over events, F1 is the
  harmonic mean, false alarms per day is false alarms over evaluated days.
- An alert already firing at the start of the evaluation period counts as firing at its first
  sample.

## Comparison models

- `fixed`: lower limit at half of the minimum and upper limit at 1.5 times the maximum seen in
  the 14 training days. This is a generous fixed threshold: a tighter one would fire at the
  normal daily trough or peak.
- `seasonal`: defaults (daily and weekly seasonality, `band_k` 6, `slot_window` 8).
- `rcf`: defaults (shingle 8, 40 trees, sample 1024, 1440 sample normalisation window).
- `rcf-time`: `rcf` with time of day and week as extra dimensions.

## Tuning and final seeds

Parameters were tuned on seeds 0 to 19. The reported run uses seeds 1000 to 1019 for scenarios
and 1500 to 1504 for normal series, which were not used for tuning.

## What this does not show

- Synthetic data is simpler than production data. Results here say the models can do the job on
  a clean yardstick, not how many false alarms a real system produces.
- Resolution is one minute. The scenario delays are floor-limited by the `for` clause.
- Only single injected events, no overlapping failures, no gradual drift.

## NAB (Numenta Anomaly Benchmark)

`anomaly-detection-nab` runs the same models on the 58 files of NAB and scores them with the
NAB score. It complements the synthetic scenarios: the data is real, the anomalies are
labelled by others, and the numbers can be put next to published detectors. It does not
replace them, because NAB has no silent failures of the kind this project targets.

```sh
uv run anomaly-detection-nab fetch --dest /path/to/nab          # data/ and labels/ only
uv run anomaly-detection-nab run --nab-dir /path/to/nab --scores-dir out/scores --workers 8
uv run anomaly-detection-nab report --nab-dir /path/to/nab --scores-dir out/scores
uv run anomaly-detection-nab verify --nab-dir /path/to/NAB-checkout   # needs results/
```

The data is not stored in this repository. `fetch` downloads the pinned revision
(`harness/nab_data.py`, `NAB_REF`), or `--nab-dir` can point at any checkout of the NAB
repository.

### Scoring

Reimplemented in `harness/nab_score.py` from the published method, without copying NAB code.

- Each labelled anomaly has a window. Per record the detector gives a score in [0, 1]; one
  threshold per detector and profile turns scores into detections.
- Only the best detection in a window counts, the earliest one. Its weight is
  `2 * sigmoid(-5 * position) - 1`, position -1 at the left edge and 0 at the right edge. A
  window without a detection costs `-fn_weight`.
- A detection outside every window is a false positive with the same sigmoid, position
  measured past the previous window's right edge in window widths, times `fp_weight`. Before
  the first window or beyond 3 widths it is -1 times `fp_weight`.
- The first `min(15 percent of records, 750)` records of every file are ignored.
- Profiles: standard (fp 0.11, fn 1), reward_low_FP_rate (fp 0.22, fn 1), reward_low_FN_rate
  (fp 0.11, fn 2). The true positive weight is 1 in all of them.
- Normalisation: 0 for the null detector (nothing detected), 100 for a perfect detector
  (all 116 windows detected at the left edge, no false positive).
- Threshold: the single value per profile that maximises the raw score over the whole corpus
  (the official `--optimize` step). The threshold is fitted on the test corpus. That is how
  NAB defines the score, but it is optimistic, so the report also gives the score at a fixed
  threshold of 0.5 and the best score among thresholds that detect something.
- Per category scores use the corpus threshold and are normalised with the null and perfect
  values of that category. NAB itself only defines the corpus score.

### Parameter rule for the models

NAB files differ in resolution (5 minutes, 10 minutes, 30 minutes, 1 hour), in length (1127 to
22695 records) and in seasonality. Every parameter is derived from two numbers that are known
before the first scored record: the sampling interval, the median positive gap of the first
100 timestamps, and the probationary length `min(floor(0.15 * n), 750)`. Values, labels and
results are never used, and nothing is tuned per file or per category.

| model | rule |
|---|---|
| `seasonal` | `slot_window = clamp(round(2400 s / interval), 1, 8)`, `min_points = min(18, 2 * (2 * slot_window + 1))`, daily and weekly seasonality, everything else default. The pooling keeps its default span of about 40 minutes at 5 minute data and shrinks to one neighbouring slot on 30 minute and hourly data |
| `rcf` | `norm_window = clamp(round(86400 s / interval), 288, 1440)`, `reference_window = max(6, round(3600 s / interval))`, `sample_size = clamp(probation - 50, 64, 1024)` so that the forest is full and scores from the end of the probationary period, everything else default (shingle 8, 40 trees) |
| `rcf-time` | `rcf` with time of day and week as extra dimensions |
| `awsrcf-nab` | not derived from the file: the fixed setting of the AWS entry in the NAB scoreboard (100 trees, sample 256, shingle 1, decay 1e-5, raw score divided by 8). Needs the Java bridge, see `docs/design.md` |
| `awsrcf`, `awsrcf-trcf`, `awsrcf-grade` | `sample_size` and `reference_window` as in `rcf`, everything else default of `models/awsrcf.py` (shingle 8, 50 trees, mode `caster`, or `trcf` without band). `awsrcf-grade` uses the anomaly grade of the library as score instead of the threshold ratio |
| `toto-4m`, `toto-22m` | no per-file rule: context 512 samples, first score after 128, score mapping at its default. The shortest file has a probationary period of 169 records, so every file is scored from the end of it |
| `tspulse` | no per-file parameter. 512 sample context, 32 sample scoring window, three heads, defaults of the model. The first score appears at record 563 of each file, whatever the probationary length is |
| `subpca` | no per-file parameter. Window 16, 0.75 of the variance, refit every 64 samples on the last 1024 windows, defaults of the model. The first score appears at record 271 of each file |
| `fixed` | lower and upper limit half the range of the probationary period below its minimum and above its maximum. The synthetic comparison (half the minimum, 1.5 times the maximum) breaks on zero and negative values, which NAB has. Score is 1 outside the limits and 0 inside |

The timestamps are read as UTC. A record whose timestamp is not later than the previous one
(NAB has a few duplicates and one backward step) is skipped by the pipeline and counts as no
detection. Seed 0 is used for RCF in every file.

### Toto 2.0 on NAB

`anomaly-detection-nab run-toto` scores the corpus with the optional `toto` model (needs the
`toto` extra and a downloaded checkpoint per size, one directory each). It does not call the
model one record at a time: `models/toto.py:score_batch` predicts many steps of one file in one
forward pass. Windows are the same as in the streaming path (the last 512 values before the
record, never including it), and a test checks that both paths give the same scores
(`tests/test_toto.py`, and with the real network when `TOTO_MODEL_DIR` is set).

Score: the value is compared with the 0.1 and 0.9 quantiles of the one-step forecast. With `d`
the distance outside the band (0 inside) and `w` the band width (at least 2 percent of the
median), `r = d / w` and `score = r / (r + 1)`. A value inside the band scores 0, one band
width beyond its edge 0.5. The mapping is monotone in `r`, so the NAB score, which picks its
threshold on the corpus, does not depend on the constant; only the fixed 0.5 threshold and the
event metrics do. The constant was set before the first run and not changed afterwards.

### Event metrics on NAB

The same alert rule as above (score at least 0.5 for 3 consecutive records). A window is a
true event; windows that end inside the probationary period are dropped and one that starts
inside it is cut. Alerts must fire after the probationary period. Detection delay is measured
from the window start. NAB windows are centred on the labelled anomaly and are about 10
percent of the file long divided over the anomalies, so the delay includes the time before the
anomaly itself and cannot be compared with the synthetic scenarios.

### What this does not show

- The NAB score is computed per record. A model that marks every record of a long deviation
  pays for each of them, while an alert rule fires once. The report therefore also scores
  `<model>+for3`, the model behind the `for: 3` clause (smallest score of the last three
  records).
- NAB scores of other detectors come from their authors and from the NAB README. They are
  shown next to ours for orientation, not as a controlled comparison.
- The rrcf based `rcf` here is not the AWS implementation that sits in the NAB scoreboard.
  The `awsrcf-*` models are (run them with `ANOMALY_AWSRCF_HOME` set, see `docs/design.md`);
  `awsrcf-nab` is the one that reproduces the scoreboard setting.

## SMD and PSM (multivariate public data)

`python -m anomaly_detection.harness.bench_cli run|report` scores the models on SMD (28
servers, 38 dimensions) and PSM (one unit, 25 dimensions). The data directories are
arguments, the data is not stored in this repository; `scripts/bench_smd_psm.sh` runs the
stages used for `docs/results/m4-smd-psm.md`.

- The models are univariate. Every dimension is scored alone, the score of a row is the
  maximum over the dimensions, the label is per row of the machine. Dimensions without variance
  over train and test together are dropped and counted.
- Train rows are the warm-up (fed to the model, not scored), test rows are scored. Time is the
  row index times 60 seconds. Missing values are skipped, never fed or zero-filled. Models with
  a finite memory (`rcf`, `tspulse`, `toto-4m`) get only the last rows of the train part that
  they can use (`WARMUP_TAIL` in `harness/bench_runner.py`).
- Operating point: the alert rule above (0.5, 3 rows, merge gap 10, grace 5) on the row score,
  events are the runs of label 1.
- Oracle: the same event F1 at the one threshold (shared by all machines of the scope) that
  maximises it on the test labels. It separates score quality from the threshold choice and is
  not an achievable result.
- Threshold free: average precision over all test rows of the scope (ties grouped), chosen over
  VUS-PR because it needs no buffer parameter.
- Point adjust F1 is printed apart as reference only; it counts a whole event as found after one
  hit and inflates every result.
- Cause: per labelled event, whether the dimension with the highest score inside the event is
  one of the dimensions the interpretation labels list for it (SMD only). Ties count as the share
  of tied dimensions that are right. The chance level is printed next to it.
- `random` rows are uniform random scores, a floor for every metric.

## Ensemble judgement layer

`anomaly-detection-ensemble` (`harness/ensemble_*.py`) scores combinations of cached model
scores. Definitions:

- unit: what an alert belongs to. A NAB file, an SMD machine (maximum over its dimensions), PSM
  as one unit, a BOOM or recorded series, a lab signal.
- windows: the warm-up of the earlier run, then a calibration window (3 days, at least 300
  samples; 2 compressed days before the first injection for the lab runs), then the evaluation
  window. Calibration uses scores only, never labels. Events that end before the evaluation
  window are dropped, one that starts earlier is cut. Alerts count in the evaluation window.
- stages: two thresholds from the same combined score, budgets 1 and 0.1 alerts per unit per
  day (settings). The alert rule is the one above (3 consecutive samples, merge gap 10, grace 5).
- labelled data: detection rate (recall), miss share, precision, false alarms per unit day (a
  unit day is one unit observed for one day), F1 pooled over units, median delay from the event
  start, share of units for which the stage can never fire (silent).
- unlabelled data: every alert is a false alarm. Pooled alerts per unit day, mean and 90th
  percentile per unit, share of units at or below the budget of the stage, silent share.
- `raw:<model>` rows are the operating rule of the earlier results (raw score at least 0.5 for
  3 samples) on the same evaluation window, both stages the same.
- `@max` rows run without tail extrapolation (thresholds from the plain maximum of the
  calibration window).
- macro average: mean over the datasets of each kind, every dataset one vote.

Composition and settings are fixed for all data sets before the run and not tuned per data set.
