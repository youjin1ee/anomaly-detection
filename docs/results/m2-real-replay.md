# 2차 마일스톤 실데이터 재생 평가 (오탐 내성)

- 실행일: 2026-11-26
- 대상: `feat/m2-qa-false-alarm` 브랜치. 1차 마일스톤 커밋에서 분기
- 실행 환경: ARM64 원격 장비, 8 프로세스 병렬, RCF 재생 소요 4423초
- 방법 정의: `docs/evaluation.md`의 알림 규칙과 지표 정의를 그대로 사용. 재생 입력과 절차는 이 문서 아래 절
- 데이터는 저장소에 없음. 수치와 해석만 기록

## 요약

- 정상 운영 트래픽이 아닌 테스트 환경 8일치를 재생. 이상 라벨이 없으므로 모든 알림은 오탐 후보
- 오탐 상한(시계열당 하루 0.1건) 기준은 점수를 낸 시계열 평균으로 판정. 고정 임계만 충족(0.010). RCF 두 변형은 보호 설정을 켜면 0.110과 0.109로 상한에 근접했지만 넘음. 계절성 기준선은 보호 설정을 켜도 1.361로 13배 초과
- 알림 원인의 다수는 트래픽 0에서 버스트로 바뀌는 구간과 그 밖의 상승. 일 주기가 없어 계절성 기준선의 같은 시각 과거값이 대부분 0이라서 생김
- 계절성 모델에 유휴 시간대 버스트 허용 옵션(`idle_scale_ratio`)을 추가. 0.2로 켜면 계절성 알림이 2620건에서 694건(보호 설정 끔 기준)으로 줄었으나 여전히 하루 0.917건으로 기준 초과
- 알림 임계 상향과 지속 시간 연장으로 기준 이하를 만드는 설정 조합은 찾음. 같은 8일 안에서 고른 값이라 과적합 가능성이 크고, 탐지율 영향은 측정하지 못함
- 테스트 시나리오 실행 흔적을 약한 라벨로 겹쳐 봤으나 일치는 우연 수준에 가까움. 알림이 실제 이상이었다고 판단할 근거는 없음
- RCF가 거의 평평한 시계열 3개에서 트리 재귀 한도 초과로 중단되는 문제를 발견해 수정

## 데이터와 방법

데이터
- LLM 서빙 클러스터의 테스트 환경에서 수집한 Prometheus 범위 질의 34개, 시계열 203개
- 구성: 서빙 엔진 26, 게이트웨이 프록시 24, GPU 익스포터 14, 노드 익스포터 16, 쿠버네티스 상태 123(재시작 증가량 시계열 118 포함)
- 약 8일, 60초 간격. 질의별 결측 비율(워밍업 뒤 구간)은 0퍼센트에서 99퍼센트까지 다양. 지연 시간 분위수와 오류율 시계열은 트래픽이 없으면 값 자체가 없음
- 특징
  - 워밍업 뒤 구간에서 요청 처리율 계열의 64퍼센트 샘플이 0, 게이트웨이 업스트림 요청률 65퍼센트가 0, GPU 사용률 89퍼센트가 0, 요청 실행 수 95퍼센트가 0
  - 일 주기가 없음. 시간대와 무관한 테스트 실행 버스트가 있을 뿐
  - 실사용 트래픽이 아니므로 이 결과는 오탐 내성의 하한을 보는 용도. 운영 환경의 오탐 수를 말하지 않음

재생 절차
- 앞 2일은 워밍업. 알림은 그 뒤 약 6일(8605샘플)에서만 셈
- 모든 시계열에 방향 both 적용(1차 마일스톤의 정상 시계열과 같은 최악 조건)
- 결측 샘플은 건너뜀. 0으로 채우지 않음
- 알림 규칙은 1차 마일스톤과 동일: 점수 0.5 이상이 3샘플 연속, 간격 10샘플 이내는 하나로 합침
- 시계열당 하루 알림 수의 분모는 워밍업 뒤 첫 샘플부터 마지막 샘플까지의 일수(최소 1일). 모델이 점수를 한 번도 내지 못한 시계열은 평균에서 제외하고 `scored` 열에 따로 표시
- 모델
  - `fixed`: 워밍업 구간 최저값의 절반과 최고값의 1.5배를 한계로 둔 고정 임계. 워밍업 샘플이 1440개 미만이면 한계를 못 정해 점수를 내지 않음
  - `seasonal`: 기본값(일, 주 계절성). 8일치라 주 계절성은 쓰이지 못해 일 계절성만 지정한 `seasonal-d`와 결과가 완전히 같음
  - `seasonal-1h`: 계절 주기를 1시간, 과거 6주기로 지정한 변형. 일 주기가 없을 때 계절성을 사실상 없앤 비교용
  - `rcf`, `rcf-time`: 기본값
- 보호 설정 켬: 시계열마다 워밍업 구간 99분위수를 대표 최대치로 보고, 하향 이동 무시 하한(`min_expected`)을 그 5퍼센트, 절대 허용 편차를 그 5퍼센트, 상대 허용 편차를 기대값의 5퍼센트로 둠. 끔은 셋 다 0. 질의마다 단위가 달라 상대 값으로 대신했고, 운영에서는 같은 크기의 절대 값을 설정
- 모델 출력은 보호 설정 적용 전 점수로 캐시하고, 보호 설정과 알림 규칙은 캐시한 점수 위에서 다시 계산. 모델 파라미터를 바꿀 때만 모델을 다시 돌림

### 알림이 몰리는 상황

알림이 시작하기 직전 30샘플을 보고 분류. 위에서부터 먼저 맞는 항목에 배정.

- gap_resume: 직전 30샘플 안에 결측이 있었음
- idle_to_burst: 직전 값이 유휴 수준(워밍업 99분위수의 1퍼센트 이하)이었다가 벗어남

- other_up, other_down: 그 밖의 상승과 하락
- no_history: 비교할 직전 값이 없음

### 보호 설정을 끄고 켠 비교

- 보호 설정은 하향 무시 하한과 허용 편차의 조합이라 0에서 버스트로 가는 상향 이동은 허용 편차 이하만 막음. 알림 감소의 대부분은 작은 편차를 무시하는 부분에서 나옴
- 계절성 보호 켬에서 idle_to_burst가 559건에서 295건으로 줄었을 뿐 남은 알림이 많음
- 보호 설정은 점수 계산 뒤에 적용되므로 점수가 이미 거의 1인 큰 버스트는 막지 못함

### 코드 변경: 계절성 유휴 시간대 버스트 허용

`seasonal` 모델에 `idle_scale_ratio`(기본 0, 꺼짐)와 `idle_level`(기본 0.05) 추가.
- 기대값이 이력 99분위수의 `idle_level` 이하이면 유휴 시간대로 보고, 흩어짐의 하한을 이력 99분위수의 `idle_scale_ratio` 배로 올림
- 이력에서 이미 나온 크기의 버스트는 이상이 아니고, 그보다 확연히 큰 버스트만 이상으로 점수화
- 기대값이 큰 시간대의 급락(요청량 붕괴 등)에는 작용하지 않음. 단위 시험으로 확인

일 계절성만 지정한 계절성 모델 기준(알림 수, 시계열당 하루)

| 설정 | 보호 설정 끔 | 보호 설정 켬 |
|---|---|---|
| 꺼짐(기본) | 2620건, 3.463 | 1030건, 1.361 |
| `idle_scale_ratio` 0.1 | 802건, 1.060 | 778건, 1.028 |
| `idle_scale_ratio` 0.2 | 694건, 0.917 | 671건, 0.887 |
| `idle_scale_ratio` 0.3 | 689건, 0.911 | 666건, 0.880 |

- 유휴 시간대에서 시작하는 서빙과 GPU 계열 알림은 거의 사라짐. 서빙 엔진 생성 토큰 처리율 계열은 하루 21.50건에서 0.08건으로 감소
- 남은 알림은 유휴가 0이 아닌 시계열이 상태를 바꾸는 경우: 노드 CPU와 네트워크, GPU 온도와 전력, 지연 시간 분위수. 유휴 수준이 0이 아니라 이 옵션의 조건에 안 맞음. 여기에는 다른 접근(상태 전환을 이력의 두 모드로 보는 방식)이 필요하며 이번 범위에서 구현하지 않음
- 계절 주기를 1시간으로 둔 변형에 0.2를 적용하면 2.058(끔)과 1.733(켬)
- 이 옵션은 기본값을 꺼 둠. 합성 데이터에서 켰을 때 탐지율 영향은 아래 합성 하네스 절 참고

### 기준 이하로 만드는 설정 탐색

탐색 방법
- 보호 설정 크기(하한 0, 0.05, 0.1, 0.2, 허용 편차 0, 0.05, 0.1, 0.2, 0.3), 알림 점수 임계(0.5, 0.7, 0.9), 지속 샘플 수(3, 10, 30) 조합 180개를 모델마다 평가
- 평가 구간 6일을 앞 절반(튜닝)과 뒤 절반(검증)으로 나눔. 값은 점수를 낸 시계열 수와 절반 일수로 나눈 시계열당 하루 알림 수. 표의 숫자는 위 표와 분모 정의가 달라 같지 않음

- 계절성 계열은 지속 샘플 수 10 이하에서는 어떤 조합도 기준을 못 맞춤. 30분 연속 이상이어야 알림이 나가는 규칙이 되어 짧은 이상은 못 잡음
- RCF는 점수 임계를 0.9로 올리면 두 구간 모두 0.1 아래. 뒤 구간 값이 0.095와 0.098이라 여유가 거의 없음
- 과적합 표시
  - 같은 8일에서 고르고 같은 8일의 뒤 절반으로 검증했으므로 독립 검증이 아님
  - 기본 설정도 앞 절반과 뒤 절반의 알림 수가 크게 다름(RCF 0.112 대 0.180). 테스트 실행량에 따라 오탐 수가 달라지는 데이터라 이 설정이 다른 날에도 유지된다는 보장 없음
  - 지속 시간 연장과 임계 상향은 이상을 놓치거나 늦게 잡는 쪽의 비용을 가지는데, 이 데이터에는 이상 라벨이 없어 그 비용을 측정하지 못함

### 약한 라벨 겹침

라벨의 정체
- 쿠버네티스 재시작 증가량 시계열에 테스트 시나리오용으로 보이는 네임스페이스 83개가 있고, 그중 20개에서 재시작이 기록됨
- 20개 중 12개는 약 6일 동안 간헐적으로 반복 재시작(크래시 루프 성격), 7개는 약 3일 구간, 1개는 10분짜리 단발
- 즉 깨끗한 장애 주입 일지가 아니라 지속적인 재시작 흔적. 이 흔적의 시각을 약한 라벨로 사용
- 라벨 창: 재시작 증가가 있는 시각 전 10분부터 후 30분까지 합침. 평가 구간의 13.9퍼센트를 덮음. 시나리오 네임스페이스가 존재한 시각 전체로 넓힌 두 번째 라벨은 22.1퍼센트를 덮음
- 재시작 시계열 자체는 라벨 원천이라 알림 집계에서 제외

겹침 결과(알림 발생 시각이 라벨 창 안에 있는 비율). 비교용으로 라벨 창을 평가 구간 안에서 무작위로 300번 돌려 놓았을 때의 겹침 비율(우연 기대치)과 그 95분위수를 같이 표시.

| model | 보호 설정 | 알림 | 재시작 라벨 겹침 | 우연 기대치 (95분위수) | 존재 라벨 겹침 | 우연 기대치 |
|---|---|---|---|---|---|---|
| seasonal | 끔 | 2609 | 0.169 | 0.214 (0.260) | 0.262 | 0.306 |
| seasonal | 켬 | 1019 | 0.320 | 0.215 (0.286) | 0.469 | 0.303 |
| seasonal 유휴 허용 0.2 | 켬 | 660 | 0.315 | 0.209 (0.280) | 0.486 | 0.303 |
| rcf | 끔 | 104 | 0.337 | 0.218 (0.414) | 0.423 | 0.293 |
| rcf | 켬 | 66 | 0.333 | 0.214 (0.425) | 0.439 | 0.291 |
| rcf-time | 끔 | 112 | 0.429 | 0.211 (0.402) | 0.500 | 0.293 |
| rcf-time | 켬 | 65 | 0.431 | 0.194 (0.431) | 0.523 | 0.293 |
| fixed | 켬 | 5 | 1.000 | 0.205 (0.600) | 1.000 | 0.294 |

- 알림 수는 재시작 시계열을 뺀 합계라 앞의 표와 조금 다름
- 보호 설정을 끈 계절성은 우연 이하로 겹침. 보호 설정을 켠 계절성은 우연 기대치의 95분위수를 약간 넘음
- RCF는 우연 기대치의 95분위수와 비슷하거나 그 안. 시각이 겹친다고 말할 수 있는 수준이 아님
- 고정 임계 알림 5건은 모두 라벨 창 안이지만 건수가 적어 의미를 두기 어려움
- 겹치는 알림을 설명 가능한 알림으로 분리하면 보호 켠 RCF의 설명되지 않는 알림은 시계열당 하루 0.095(rcf)와 0.080(rcf-time)으로, 보호 켠 계절성은 1.491로 남음
- 근거 수준: 시각 일치뿐. 인과도, 알림이 실제 이상이었는지도 확인하지 못함. 겹치지 않는 알림이 오탐이라는 뜻도 아님. 테스트 실행 흔적이 불완전하고 라벨 창이 넓음

### RCF 재귀 한도 초과

- 거의 평평한 시계열 3개(GPU 메모리 사용량, 노드 준비 상태, 재시작 증가량 하나)에서 rrcf 트리가 한쪽으로 쏠린 사슬 모양이 되어 `RecursionError`로 중단
- 사이드카에서는 탐지기 스레드가 죽을 수 있는 문제
- 수정: 재귀 한도를 넘으면 숲을 새 시드로 다시 만들고 표본이 다시 찰 때까지 점수 없이 진행. 재설정 횟수를 `resets`로 노출
- 수정 뒤 3개 시계열 모두 끝까지 재생(점수 산출 샘플 8375개에서 9339개)
- 정규화 값 클리핑을 먼저 시도했으나 원인이 아니어서 넣지 않음

## 합성 하네스 회귀

1차 마일스톤과 같은 조건(시나리오당 변형 20회, 시드 1000부터, 정상 시계열 신호당 5개, 6 프로세스 병렬, 소요 13130초)으로 하네스를 다시 돌려 `docs/results/m1-baseline.md`와 비교함.

- `fixed`, `seasonal`, `rcf`, `rcf-time`의 시나리오 표 16행과 정상 시계열 표 16행이 1차 결과와 모든 열에서 일치. 회귀 없음
- 예상된 결과. 계절성 옵션은 기본값이 꺼져 있고, RCF 변경은 재귀 한도 초과 때만 동작하는 경로
- 유휴 허용을 0.2로 켠 `seasonal-i20`도 합성 데이터에서는 기본 계절성과 같은 결과: 탐지율 4개 행 모두 100퍼센트, 오탐 0건, 탐지 지연 중앙값 동일
- 샘플당 비용은 `seasonal` 21마이크로초, `seasonal-i20` 171마이크로초. 이력 99분위수를 매번 계산하는 비용이며 1분 간격에서는 무시할 수준
- RCF 샘플당 비용은 `rcf` 11732, `rcf-time` 12227마이크로초(1차는 10024, 11591). 장비 부하 차이로 추정

## 이 평가가 보여주지 못하는 것

- 이상 라벨이 없어 탐지율과 정밀도를 구하지 못함. 오탐 상한도 후보 수일 뿐
- 하나의 테스트 환경 8일이라 일반화 어려움. 일 주기가 있는 운영 데이터에서는 계절성 기준선의 결과가 크게 달라질 수 있음
- 주 계절성은 8일 안에서 쓸 수 없어 평가하지 못함
- 보호 설정의 크기를 시계열별 상대값으로 근사함
- 설정 탐색 결과는 같은 데이터 안에서의 선택이라 과적합 가능성이 큼
- 탐지 지연과 재현율은 이 데이터로 측정하지 못함. 임계 상향과 지속 시간 연장의 탐지 영향은 합성 데이터로도 측정하지 않음
