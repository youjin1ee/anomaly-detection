# 4차 마일스톤 BOOM 재생 평가 (운영 지표 오탐)

- 실행일: 2026-11-26부터 27
- 대상: `feat/m4-bench-boom` 브랜치. 3차 마일스톤 통합 커밋에서 분기
- 실행 환경: ARM64 원격 장비, CPU 코어 4개 고정, 프로세스 4개 병렬, 낮은 우선순위, 메모리 16GB 상한, GPU 미사용. 실행 중 장비 부하 평균은 20에서 40
- 방법 정의: `docs/evaluation.md`의 알림 규칙과 `docs/results/m2-real-replay.md`의 재생 방식을 그대로 사용. 이 문서는 입력, 모델 파라미터 규칙, 새 집계만 추가로 정의
- 데이터는 저장소에 없음. 수치와 해석만 기록

## 요약

- 이상 라벨이 없는 실제 관측 지표 991개(변량 단위)를 8개 모델에 재생. 모든 알림은 오탐 후보
- 모델 8개 전부를 돌린 층화 부분집합(60개 시계열)에서 보호 설정을 켠 시계열당 하루 알림 수 평균
  - awsrcf-nab 0.069, 고정 임계 0.076, rcf 0.106, toto-4m 0.109, subpca 0.149, tspulse 0.205, seasonal 0.940, awsrcf 1.483
  - 평균이 0.1 이하인 모델은 awsrcf-nab와 고정 임계뿐. 둘 다 평균의 95% 구간이 0.1을 걸침
- 기준(하루 0.1건 이하)을 충족한 시계열 비율은 고정 임계 83%, toto-4m 83%, awsrcf-nab 75%, rcf 62%, subpca 55%, tspulse 52%, seasonal 28%, awsrcf 5%
- 같은 모델도 표본에 따라 수치가 크게 달라짐. 고정 임계는 부분집합 60개에서 0.076, 120개에서 0.158, 전체 991개에서 0.135. 모델 순위보다 수치 크기를 믿어야 하는 정도가 낮음
- 보호 설정은 모든 모델에서 알림을 줄이지만 순위는 rcf와 toto-4m 순서만 바꿈. rcf(93건에서 66건)와 awsrcf(1288건에서 909건)가 약 29퍼센트로 가장 많이 줆
- 해상도: 부분집합 B에서 고정 임계를 뺀 모델 모두 1분 시계열이 5분보다 하루 알림이 2.5배에서 14배 많음(seasonal 2.0 대 0.40, toto-4m 0.286 대 0.021, rcf 0.187 대 0.065). 고정 임계는 B에서 반대, 전체에서는 같은 방향
- 동시 알림: 전체 991개에서 같은 10분 창에 알림을 낸 시계열은 최대 18개(고정 임계)에서 36개(seasonal). 알림의 9퍼센트에서 20퍼센트가 5개 이상 시계열이 함께 낸 창에 속함
- 오탐 예산 보정: 워밍업 뒤 2일 구간에서 알림이 0건이 되는 가장 낮은 임계를 시계열마다 정하면, 임계 하한을 0.5로 두었을 때 5개 모델(subpca, awsrcf-nab, toto-4m, tspulse, rcf)이 예산 0.1 안(0.029에서 0.086)에 들어옴. seasonal(0.167)과 awsrcf(0.359)는 넘음. 하한을 두지 않으면 subpca, awsrcf-nab, toto-4m, rcf가 0.247에서 0.478로 예산의 2.5배에서 5배를 넘김
- 이 평가는 오탐만 잰 것. 탐지율을 모르므로 알림이 적다고 좋은 모델이라고 할 수 없음

출처와 라이선스

- 카드 설명: 사전 운영 환경의 내부 모니터링에서 수집한 메트릭이며 고객 데이터를 포함하지 않음

부분집합
- 원본 2807개 중 해상도 1분(150개)과 5분(150개), 추정 길이 7일 이상인 300개를 (해상도, 도메인, 지표 유형) 57개 층에서 시드 0으로 추출. 선택 기준과 목록은 데이터 폴더의 `SELECTION.txt`와 `MANIFEST.csv`
- 변량별로 풀어 991개 단변량 시계열(1분 480개, 5분 511개). 목록의 변량 합계는 993개이나 `ds-378-T`의 arrow 파일에는 6개가 아닌 4개만 있음. 원인은 확인하지 못함
- 길이: 16384점이 대부분. 1분은 16384점(약 11.4일)이 474개, 15619점 5개, 15360점 1개. 5분은 16384점(약 56.9일)이 402개, 13631점(약 47.3일) 109개
- 시작 시각이 52가지. 변량이 같은 시계열은 시작 시각이 같고, 5분 시계열 154개, 170개, 109개가 각각 같은 날짜 구간을 공유
- 지표 유형: gauge 424, rate 294, distribution 171, count 102. 도메인은 12가지 조합

공개본의 특성과 처리
- 값이 변량별 z-score로 정규화되어 있음(평균 0, 표준편차 1). 0이 유휴 상태를 뜻하지 않음. 한가한 카운터는 최빈값(예: -0.0325)에 머묾
- 보호 설정의 하한과 허용 편차, 유휴 판정이 0 기준 상대값이라 그대로는 의미가 없음. 그래서 시계열마다 워밍업 구간의 1분위수를 빼서 유휴가 0 근처에 오게 함(`rebase_days`). 상수 이동이라 이동과 크기에 둔감한 모델은 영향이 없고, 워밍업 값만 쓰므로 미래 정보가 들어가지 않음
- z-score의 평균과 표준편차를 어느 범위로 계산했는지는 확인하지 못함. 전체 구간으로 계산했다면 크기 배율에 평가 구간 정보가 섞여 있음
- 데이터 카드에 따르면 결측은 보간되어 있음. 결측이 있는 시계열이 없어서 결측 후 재개(gap_resume) 알림은 이 데이터에서 0건일 수밖에 없음
- 길이가 16384점으로 맞춰져 있어 원본에서 잘렸을 가능성이 있음. 확인하지 못함

## 방법

재생 절차
- 앞 2일은 워밍업(1분 2880샘플, 5분 576샘플). 알림은 그 뒤 구간에서만 셈
- 방향은 모두 both. 알림 규칙은 점수 0.5 이상 3샘플 연속, 간격 10샘플 이내는 하나로 합침
- 시계열당 하루 알림 수의 분모는 워밍업 뒤 첫 샘플부터 마지막 샘플까지의 일수
- 보호 설정 켬은 m2와 같음: 워밍업 구간 99분위수(이동 후)의 5퍼센트를 하향 무시 하한과 절대 허용 편차로, 기대값의 5퍼센트를 상대 허용 편차로 둠. 끔은 셋 다 0
- 모델 출력은 보호 설정 적용 전 점수로 캐시하고 보호 설정과 알림 규칙은 캐시 위에서 다시 계산

기준 충족 비율의 해석 주의
- 충족은 시계열의 하루 알림 수가 0.1 이하인 것
- 평가 구간이 1분 시계열은 약 9.4일, 부분집합의 5분 시계열은 12일이라 알림 1건이 1분에서 0.106, 5분에서 0.083으로 환산됨. 1분은 알림이 0건이어야 충족이고 5분은 1건까지 충족
- 그래서 해상도 간 충족 비율 비교에는 이 차이가 섞임. 평균 알림 수는 이 영향이 없음
- 시계열 전체 길이를 쓰는 실행(`allfull`)은 5분 시계열 평가 구간이 약 55일

모델과 파라미터 규칙. 값과 라벨, 결과로 시계열마다 조정한 것은 없음
- `fixed`: 워밍업 최저값에서 범위의 절반을 뺀 값과 최고값에 범위의 절반을 더한 값을 한계로 둠. m2의 규칙(최저값의 절반, 최고값의 1.5배)은 0과 음수에서 깨지고, 이동 후 값에서 최저값이 0 근처라 쓸 수 없음. NAB와 같은 이유로 같은 범위 규칙을 선택. 워밍업 샘플이 하루치 미만이면 점수를 내지 않음. 데이터 특성(z-score, 음수와 0 근처 값)을 보고 정한 규칙이고 시계열별 조정은 없음. 한계 안은 0점, 밖은 1점
- `seasonal`: 기본값(일, 주 계절성, 슬롯 폭 8). 주 계절성은 2주치 이력이 있어야 쓰이므로 1분 시계열(약 11.4일)에서는 쓰이지 않음
- `rcf`(rrcf): 표본 크기 = 워밍업 샘플 수에서 50을 뺀 값을 64와 1024 사이로 제한. 워밍업이 끝날 때 숲이 차게 함(1분 1024, 5분 526). 정규화 구간과 기준 구간은 샘플 간격에서 NAB 규칙으로 계산(1분 1440과 60, 5분 288과 12)
- `awsrcf-nab`: NAB 점수판의 AWS 항목 설정(트리 100, 표본 256, 셔플 1, 감쇠 1e-5, 원점수를 8로 나눔). 시계열과 무관
- `awsrcf`: `rcf`와 같은 표본 크기와 기준 구간, 모드 `caster`, 나머지는 기본값(셔플 8, 트리 50)
- `tspulse`: 기본값. 512샘플 문맥, 첫 점수는 563번째 샘플. 배치 경로로 재생(스트리밍 경로와 같은 점수를 내는 것을 시험으로 확인)
- `toto-4m`: 기본값. 문맥 512, 최소 128. 배치 경로로 재생
- `subpca`: 기본값

재생 규모
- 전체(`all14`): 991개 전부, 앞 14일만 사용(5분 시계열은 4032점). 모델은 fixed, seasonal, subpca, awsrcf-nab, awsrcf. 점 9,919,823개
- 전체 길이(`allfull`): 991개 전부, 잘라내지 않은 길이. 모델은 fixed, seasonal, subpca. 점 약 1600만개
- 부분집합 B(`subsetB`): 8개 모델 모두. 1분 20개, 5분 40개, 앞 14일, 점 487,171개
- 부분집합 A(`subsetA`): B를 포함하는 더 큰 부분집합. 1분 40개, 5분 80개, 점 975,366개. toto-4m까지 6개 모델
- 부분집합 선정: 목록의 시계열마다 변량을 하나만 뽑고(같은 질의의 변량은 서로 닮아서), (해상도, 도메인, 지표 유형) 층을 돌아가며 시드 0으로 뽑음. A와 B는 포함 관계. B의 지표 유형은 count 10, distribution 13, gauge 23, rate 14
- tspulse와 rcf는 재생이 느려서 B에서만 돌림. 전체와 A는 4시간 예산 안에 들어가지 않음
- 부분집합 B와 전체 14일의 모든 모델에서 모델 오류로 중단된 시계열은 0개

### 오탐 예산 보정 실험

방식(`replay.calibrated_threshold`)
- 시계열마다 워밍업 2일 뒤의 2일을 보정 구간으로 씀(일 2에서 4). 워밍업 구간은 쓰지 않음. seasonal이 2일치 이력이 있어야 점수를 내고 다른 모델도 워밍업 중에는 점수가 불안정해서 점수가 있는 구간을 따로 잡음
- 보정 구간에서 실제 알림 규칙(3샘플 연속, 합침)으로 센 알림이 예산 곱하기 일수(0.1 곱하기 2일 = 0.2건) 이하가 되는 가장 낮은 임계를 이분 탐색으로 찾음. 0.2건 이하는 0건이므로 임계는 보정 구간의 가장 높은 3샘플 연속 점수 바로 위

## 한계와 확인하지 못한 것

- 탐지율은 알 수 없음. 라벨이 없어서 알림이 오탐인지 진짜 이상인지 판정하지 못함. 알림이 적은 모델이 좋은 모델이라는 결론은 내릴 수 없음
- 데이터가 z-score 정규화와 결측 보간을 거쳤고 길이가 잘렸을 수 있음. 원본 값 기준의 0 이상 한계, 결측 처리, 원 단위의 보호 설정은 검증하지 못함. 워밍업 1분위수 이동은 이 문서에서 정한 대체 처리
- 8개 모델을 모두 비교한 표본은 60개 시계열. 모델 순위가 안정적이라고 보기 어렵고 큰 표본에서 낮은 모델 쪽이 높게 나옴
- tspulse와 rcf는 전체와 A에서 재지 못함. toto-4m은 전체에서 재지 못함
- 평가 구간이 1분 9.4일, 5분 12일이라 하루 0.1건 기준은 알림 1건 단위로 갈림. 시계열 수준 충족 비율은 거칠고, 평균과 합산 지표를 같이 봐야 함
- 같은 질의의 변량이 여러 개인 전체 991개는 독립 표본이 아님
- 모델 파라미터는 NAB 규칙을 그대로 따름. BOOM에 맞춘 튜닝은 하지 않음. 다른 설정에서 결과가 달라질 수 있음
- awsrcf(caster)와 awsrcf-nab의 알림 수가 20배 정도 차이 나는 원인(셔플 8과 임계 비율 점수 대 셔플 1과 원점수)은 이 실험에서 분해하지 않음
- 해상도 차이의 원인은 가설일 뿐 확인하지 않음
- 단위 시험은 원격 장비에서 155개 통과, 1개 건너뜀(NAB 체크아웃이 필요한 시험)

## 재현

데이터는 로컬 사본의 경로를 인자로 줌. 저장소에 넣지 않음

```sh
uv sync --extra toto --extra tspulse --extra boom
export TOTO_MODEL_DIR=... TSPULSE_MODEL_DIR=... ANOMALY_AWSRCF_HOME=... ANOMALY_AWSRCF_JAVA=...
anomaly-detection-boom /path/to/boom --cache-dir cache --out-dir out --tag subsetB \
    --max-days 14 --subset 20,40 --workers 4 \
    --models fixed,seasonal,rcf,awsrcf-nab,awsrcf,tspulse,toto-4m,subpca
python scripts/boom_report.py out/subsetB.json
```

- `--subset N1,N5`: 1분 N1개와 5분 N5개를 층화 선택(시드 `--subset-seed`)
- `--max-days`: 시계열 앞쪽 일수만 사용
- `--skip-run`: 캐시된 점수만 다시 집계
- 보호 설정과 알림 규칙, 보정 방식은 캐시한 점수 위에서 다시 계산하므로 모델 재생 없이 바꿔 볼 수 있음
