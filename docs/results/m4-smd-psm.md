## 평가 설계

- 집계: 모델이 단변량이라 차원마다 따로 점수를 내고, 서버(PSM은 전체) 한 행의 점수는 차원 점수의 최댓값. 라벨은 서버 단위
- 상수 차원: train과 test를 합쳐 분산이 0인 차원은 제외. SMD 28대 1,064차원 중 175개가 제외되어 889개를 씀. PSM은 0개. 앞 10,000행으로 자른 SMD 3대 범위에서는 시험 구간이 짧아 제외가 13개(전체 시험 기준 12개)
- 워밍업: train 행을 모델에 먼저 흘려 보내고(점수는 버림) 이어서 test 행을 점수화. 시간은 train 끝에서 test로 이어짐
  - 빠른 모델(fixed, seasonal, awsrcf-nab, awsrcf, subpca)은 train 전체를 워밍업으로 사용
  - 기억 길이가 유한한 느린 모델은 train의 끝부분만 사용. rcf 3,000행(숲 1,024와 정규화 창 1,440), tspulse 2,600행(문맥 512와 점수 이력 2,000), toto-4m 512행(문맥)
- 결측 처리: 모델에 결측을 넣지 않고 건너뜀. 0으로 채우지 않음. 건너뛴 test 행의 점수는 없음으로 두고 알림 규칙에서 연속을 끊음. PSM train 결측은 모두 워밍업 구간이라 영향은 건너뛴 행뿐. PSM의 train 마지막 행과 test 첫 행이 같은 분 인덱스(132480)여서 train 쪽 한 행을 뺌
- 모델별 파라미터(NAB와 같은 규칙, 값과 라벨과 결과에 의존하지 않음, 서버나 차원별 조정 없음)
  - seasonal: 간격 60초 기준 `slot_window` 8, `min_points` 18, 일간과 주간 주기
  - rcf: 정규화 창 1,440, 기준 창 60, 표본 1,024. 숲을 채우는 길이가 워밍업보다 훨씬 짧아서 NAB의 표본 크기 규칙 대신 모델 기본값 1,024를 씀
  - awsrcf: caster 모드, 표본 1,024, 기준 창 60
  - awsrcf-nab: 모드 rcf, NAB 점수표 항목의 설정(트리 100, 표본 256, shingle 1, 감쇠 1e-5, 원점수를 8로 나눔)
  - subpca, tspulse, toto-4m: 모델 기본값(subpca 창 16, tspulse 문맥 512와 점수 창 32, toto 문맥 512와 최소 128)
  - rcf와 awsrcf 계열은 시드 0 하나
  - fixed: train 구간 최소와 최대에서 범위의 절반만큼 바깥을 한계로 둠. NAB에서 쓴 규칙을 그대로 가져온 것이고 이 데이터에서 값을 보고 고르지 않음. 데이터가 0에서 1로 정규화되어 있어 NAB에서 문제가 된 0과 음수 값 이슈는 없음. 민감도를 보려고 여유를 0으로 한 fixed-tight(train 최소와 최대 그대로)를 함께 냄. 점수는 한계 밖 1, 안 0이라 이진
- 느린 모델의 워밍업 끝부분 사용과 모델 호출 방식은 기존 NAB 실행 경로의 배치 호출(`score_offline`, `score_batch`)과 같음. tspulse와 toto는 배치 경로가 스트리밍 경로와 같은 값을 낸다는 기존 테스트에 의존하고 이번에 새로 대조하지는 않음
- 지표
  - 운영 알림 규칙: 점수 0.5 이상이 3행 연속이면 알림, 알림 사이 간격 10행 이하는 하나로 합침, 이벤트 시작부터 끝 5행 뒤까지 알림이 나오면 탐지. 이벤트는 라벨 1의 연속 구간. 서버 전체를 합산(micro)한 정밀도, 재현율, F1. 탐지 지연은 이벤트 시작부터 알림까지 분 중앙값. 오탐은 하루당(평가 일수 기준)
  - 오라클 F1: 위와 같은 이벤트 F1을 임계값만 바꿔가며 test 라벨로 최댓값을 고른 값. 서버 전체에 임계값 하나. 점수 품질과 임계 문제를 떼어 보려는 용도이고 실제로 얻을 수 있는 값이 아님. 임계 후보는 0.05에서 0.95까지 0.05 간격과 0.97, 0.98, 0.99, 0.995, 0.999, 0.9999. 이진 점수인 fixed는 후보와 상관없이 같은 값이라 임계 칸의 0.05는 의미가 없음
  - 임계 없는 지표: AP(평균 정밀도, 행 단위 PR 곡선 아래 면적). VUS-PR 대신 고른 이유는 구현이 몇 줄이고 버퍼 길이 파라미터가 필요 없어서. 같은 점수는 한 단계로 묶음. 점수가 없는 행은 0으로 취급. 범위 안 모든 서버의 행을 합쳐 계산
  - point adjust F1: 이벤트 안에서 한 점만 맞혀도 이벤트 전체를 맞힌 것으로 치는 방식. 과대평가로 비판받는 방식이라 참고용으로 따로 표시
  - 원인 지목: 라벨 이벤트마다 그 안에서 점수가 가장 높은 차원이 해석 라벨에 적힌 차원에 드는지. 이벤트와 겹치는 해석 구간의 차원 합집합을 정답으로 봄. 최고 점수가 같은 차원이 여럿이면 그중 정답 비율만큼 점수를 줌(무작위로 하나 고를 때의 기대값). 표의 chance는 사용 가능한 차원 중 무작위로 하나 고를 때의 기대 비율. 해석 라벨이 없는 이벤트는 제외(SMD 이벤트 327개 중 325개 사용)
  - 해석 라벨 구간은 행 번호가 0부터이고 끝은 포함하지 않는 구간(`start-end`)임을 라벨 이벤트와 대조해 확인함(서버별 첫 이벤트의 시작과 끝이 해석 구간과 일치하고 machine-1-1만 끝이 27행 더 김). 차원 번호는 1부터(값이 1에서 38) 시작해 0부터로 바꿈
  - `random` 행은 균등 난수 점수. 모든 지표의 바닥선
- 평가한 범위(계산 예산 때문에 모델마다 다름)

| 범위 | 데이터 | 모델 |
|---|---|---|
| SMD 28대 | test 전체 | fixed, fixed-tight, seasonal, awsrcf-nab, subpca |
| SMD 8대 | test 전체 | 위 모델과 awsrcf |
| SMD 3대 | test 앞 10,000행 | 모든 모델(rcf, tspulse, toto-4m 포함) |
| PSM 전체 | test 87,841행 | fixed, fixed-tight, seasonal, awsrcf-nab, awsrcf, subpca |
| PSM 앞 20,000행 | test 앞 20,000행 | 모든 모델 |

- 부분 집합 선택 규칙: 모델 결과를 보지 않고 서버의 묶음(machine-1, 2, 3)별 크기에 비례해 서버 수를 배분하고 묶음 안에서 test 라벨 비율 순위가 고르게 퍼지도록 고름. 8대는 machine-1-4, 1-7, 2-3, 2-4, 2-5, 3-2, 3-3, 3-9. 3대는 이 8대 안에서 같은 규칙으로 고른 machine-1-7, 2-5, 3-3. 이 선택에는 라벨 비율을 썼지만 모델 점수는 쓰지 않음
- 앞부분 행만 쓰는 범위의 점수는 전체 실행의 점수를 앞에서 자른 값과 같음(모델이 행을 순서대로 보는 온라인 방식이므로). 그래서 빠른 모델의 같은 범위 결과는 전체 실행 점수를 잘라서 냄. 앞 10,000행과 20,000행에서 끝나지 않는 이벤트는 잘림
- PSM 앞 20,000행의 라벨 비율은 19.3퍼센트로 전체 test의 27.8퍼센트보다 낮음. SMD 3대 앞 10,000행은 이벤트 25개
- 계획 변경 기록: 처음에는 SMD 3대의 test 전체와 PSM 앞 40,000행을 계획했음. 첫 8개 차원 작업에서 tspulse가 차원당 약 9분이 걸려(공유 장비 부하) 3대 전체는 4시간을 넘길 것으로 보여 실행 도중에 SMD 앞 10,000행과 PSM 앞 20,000행으로 줄임. 이미 끝난 tspulse 8개 차원의 점수는 잘라서 재사용

## 읽는 방법과 한계

- 운영 규칙 F1과 오라클 F1의 차이가 큰 모델은 점수 순서는 쓸 만한데 0.5가 맞지 않는 경우. awsrcf가 대표적(SMD 8대 0.058 대 0.614, PSM 0.285 대 0.623). 오라클 임계가 0.9999인 행은 점수가 거의 1에 붙은 상태에서만 정상과 구분된다는 뜻이고 실제 도입 때 임계를 따로 정해야 함
- 오라클 F1은 test 라벨로 임계를 골라서 낙관적임. 운영 규칙 F1이 실제에 가까움
- 서버 점수를 차원 최댓값으로 합쳐서 차원이 많을수록 오탐이 늘어나는 구조. 오탐 하루당 수치는 이 집계 방식의 결과
- 무작위 점수의 AP가 데이터셋의 라벨 비율 근처(SMD 0.042, PSM 0.277)로 나와서 AP의 바닥선 확인용으로 씀. PSM은 이 바닥선이 높아서 모델 간 AP 차이가 작아 보임
- 이벤트 단위 점수는 이벤트 길이가 매우 다른 데이터(SMD는 3행짜리부터 수백 행까지)의 영향을 받음
- 범위 한계
  - rcf, tspulse, toto-4m은 SMD 28대에서 돌리지 않았고 SMD 3대 앞 10,000행(이벤트 25개)과 PSM 앞 20,000행(이벤트 23개)이 전부. 승패를 가르기에는 표본이 작음
  - awsrcf는 SMD 28대 중 8대만 돌림
  - rcf와 awsrcf 계열은 시드 하나. NAB 실험에서 rcf는 시드에 따라 점수가 흔들렸음
  - SMD는 타임스탬프가 없어 1분 간격이라는 공식 설명을 가정. seasonal은 이 가정에서 일간과 주간 주기를 씀. SMD의 일 주기 자기상관 중앙값이 0.46이어서 seasonal의 결과가 약한 것이 모델 문제인지 가정 문제인지 구분하지 못함
  - 모든 결과는 train이 정상이라는 가정에서 워밍업함. SMD와 PSM의 train에 라벨은 없으므로 train 안에 이상이 섞여 있어도 걸러내지 않음
  - toto-4m은 모델 크기 4m 체크포인트 하나만 평가. 22m은 이번 범위 밖
- 확인하지 못한 것
  - tspulse와 toto 배치 경로가 이번 데이터에서 스트리밍 경로와 같은 값을 내는지 직접 대조하지 않음(기존 테스트와 NAB 실행에 의존)
  - SMD 28대 전체에서 awsrcf, rcf, tspulse, toto-4m의 결과
  - 시드에 따른 변동
  - 문헌 점수와의 대조. point adjust 기준의 공개 점수는 이 문서의 지표와 달라 비교하지 않음
